## 1. The version guard (your §4.3), built

Twice in consecutive rounds output changed while the version did not, and both
times the consequence was a valid older record reading as **tampering**. Both
times a human was supposed to remember a constant. That is now a build
failure.

- **Immutable per-version fixtures.** `tests/golden/projection_v<N>.json`
  holds `(input, expected)` for a corpus of the classes these rounds have
  produced — token-shaped keys, hostile keys, the withheld marker in
  current/legacy/forged forms, nested business fields, tool calls, governance
  details.
- **The generator refuses to overwrite** an existing fixture. Changing what
  the projector emits is therefore only resolvable by a new version.
- **Coverage is your list**: every asset kind (asserted against `SCHEMAS`, so
  a new kind cannot arrive unguarded), repeated projection as a fixed point,
  reconstruction of historical records, schema-version consistency.

**Two proofs it fires** — a guard never shown to fail is decoration, which is
the fig leaf this line has caught in my work twice:

| Simulation | Result |
|---|---|
| released one business field, version untouched | **FAILED**, naming the drift |
| relabelled round-7 behaviour as `"3"` (the shipped defect) | **FAILED** |

**The historical fixture is real history.** `projection_v3.json` was
regenerated by loading the archived round-6 projector from git `4d9f39c` and
running the same corpus through it — it retains business fields, exactly as
you reproduced. Without it the degradation property would have sat *skipped*
for want of an older version, leaving the twice-broken property untested.

## 2. End-to-end coverage (your closing ask)

`backend/tests/test_trace_ownership_end_to_end.py` drives the real engine with
safe-only storage on and asserts on **persisted** state, because that is how
you found these and a projector-level test would have passed while #1 was
live:

- one run, **both surfaces** — the stored step row and the stored instance
  context — withhold model-derived scores and both carry the withheld signal;
- a function returning its config cannot get `model`, `memory_hash`,
  `projector_version`, `projection_schema_version` or an unearned `parse_ok`
  into the stored output;
- the boundary drops the forgery **without destroying the real output** — the
  vault still carries it, so a grant holder recovers what an ordinary reader
  cannot, and the forged engine field is not stored anywhere.

That third assertion was wrong in my first draft (it expected an undeclared
field to survive in the projection) and the failure was the code being right.
